# Отпуск: изолированный кандидат

## Границы
Изменения только в копии календаря. Действующий релиз, сервис и пользовательская база не обновлялись. Не запускались npm install, миграция рабочей БД или публикация. node_modules — ссылка на зависимости исходного релиза.

## Реализовано
- Создание отпуска по включительному диапазону дат, фактическая сумма NET в рублях/копейках, отметка выплаты и необязательная дата.
- Список отпусков и маркеры на календаре; ошибки сервера сохраняют введённые значения.
- Отпуск исключается из индивидуальной нормы и взаимозачёта переработок. Отдельное уменьшение оклада за плановые часы отпуска. Предпраздничный день 7 ч, праздник 0 ч.
- computeMonthPay — единый источник денежных итогов dashboard. Целые копейки итогов; промежуточные часовые ставки могут быть дробными. Половины сохраняют сумму месячного оклада до уменьшений.
- Начисления = оплата работы + переработки + отпускные независимо от отметки выплаты. Выплаченные и оставшиеся отпускные показываются отдельно. Учёт фактических выплат зарплаты не реализован, поэтому итоги половин — начисления, не банковский остаток к переводу.
- Отдельная строка отпускных в месячном расчёте и каждой половине.
- UI блокирует запись часов на дни отпуска, включая массовую операцию. Существующие часы не удаляются. API создания отпуска отклоняет пересечения с записанными часами/отпусками, возвращая 409.
- GET/POST/PATCH/DELETE /api/vacations с изоляцией по владельцу, валидацией и миграцией таблицы.

## Проверенный пример
Фикстура теста, а не запись в пользовательскую БД: 2–8 ноября 2026, 7 календарных / 6 оплачиваемых дней (4 ноября исключено из оплачиваемых дней), 31 плановый рабочий час, отпускные 26 068 ₽. При окладе 135 000 ₽, без иных отклонений и переработок: уменьшение оклада 26 156,25 ₽, оплата работы 108 843,75 ₽, начислено 134 911,75 ₽. Выплата отпускных не меняет начисления.

## Осознанные ограничения
- Только календарь 2026 года. Это учёт фактических отпускных NET, НЕ восстановление среднего заработка/НДФЛ и НЕ замена расчёта бухгалтерии.
- Сохранён старый знаменатель уменьшения оклада: рабочие дни месяца × 8. Это конвенция приложения, не утверждение о точном совпадении с расчётом 1С; возможны отличия в месяцах с сокращёнными днями. Перед публикацией требуется отдельно согласовать переход на точную часовую норму либо дневной расчёт.
- Проверка пересечений и запись API не заключены в общую транзакцию: параллельные запросы требуют дополнительной защиты. Обратная серверная защита маршрута записи часов после создания отпуска не заявляется; UI не заменяет такую защиту.
- PATCH/DELETE существуют в API, кнопки редактирования/удаления сохранённых отпусков в UI пока не реализованы.
- Экспорт Excel не адаптирован полностью к отдельным столбцам отпуска: расчёт месячного дохода обновлён, но детализация выгрузки требует отдельной проверки перед использованием.
